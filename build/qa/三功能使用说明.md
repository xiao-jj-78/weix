# 三功能使用说明（一键登录 / 通讯录+聊天 / 独立宿主插件）

> 配套产物：`微信工作台-MAUI-Android.apk`（手机端，30,538,357 B / SHA-256 `f9be504a4343…5097b`）＋ `微信SDK宿主/`（Windows 端宿主，含 `微信自动化控制台.exe` 与 `plugins/`）。
> 合规边界：**仅本人已登录账号 / 本机本地只读 / 不注入微信 / 登录不自动填凭据**。
>
> 说明：早前交付中曾出现名为 `微信工作台-MAUI-Android-三功能版.apk` 的文件，实为一份**不含「微信数据」页的 Debug 副本**，已作废撤回。本页所有引用一律以 `微信工作台-MAUI-Android.apk` 为准。

## 架构（为什么分两端）
微信 SDK（`WeChatAuto.SDK`）只能驱动 **Windows 桌面微信 4.x**。因此：
- **Windows 端**运行 `微信SDK宿主/微信自动化控制台.exe`（即 `WeChatSdkHost`），它绑定 **127.0.0.1:18766**，通过公开 UIA 读取本人数据。
- **手机端** APK 本身**不跑 SDK**，经同一局域网连到 Windows 宿主，由宿主代跑读取后回传 JSON。

## 第一步：启动 Windows 宿主
```
cd 微信SDK宿主
微信自动化控制台.exe --port 18766
# 或 WeChatSdkHost.exe --port 18766
```
- 确认本机已安装并登录官方微信 4.x（且主窗口开放辅助功能/UI Tree）。
- 宿主只接受 loopback + 同源 JSON；远程无法上传或执行插件（安全闸）。

> ⚠️ **别把两个「微信自动化控制台.exe」搞混**：`微信SDK宿主/` 里的这个（约 160 KB）是**宿主** `WeChatSdkHost` 的改名副本，只为方便双击；交付目录**顶层**那个（约 145 MB）是桌面控制台程序（Python 打包）。要跑三功能，进的是 `微信SDK宿主/` 里那个。

## 第二步：手机端连接 + 使用
1. 安装并打开 `微信工作台-MAUI-Android.apk`。
2. 「工作台」页填 **电脑 IP : 18766**（本机调试直接 `127.0.0.1:18766`）→ 连接电脑。
3. 切到「**微信数据**」页：
   - **一键登录微信**：仅打开官方微信登录窗口，由你本人扫码/确认（不自动填凭据）。
   - **读取通讯录（用户表）**：列出本人通讯录姓名（来自 `GET /api/sdk/contacts`）。
   - **读取聊天记录**：填 `who`（会话标识，如 `filehelper` 或好友备注）→ 读取本人该会话历史（来自 `GET /api/sdk/chat?who=`）。
   - **导出 CSV**：把通讯录与聊天写入本机文件 `wechat_data_*.csv`（路径会显示在页面上，透明、仅本地）。

## 第三步（可选）：以「独立宿主插件」方式调用
宿主已加载 `plugins/WeChatSdk.OwnDataPlugin.dll`（id=`own-data`）。可用任意 HTTP 客户端调用：
```
POST http://127.0.0.1:18766/api/sdk/plugins/run
Content-Type: application/json
{ "id": "own-data", "operation": "contacts" }          # 或 "login" / "chat"（chat 需 "who"）
# chat 例：{ "id":"own-data", "operation":"chat", "who":"filehelper" }
```
- 插件跑在宿主进程内、**绝不进微信进程**；只复用宿主已有的只读 SDK 桥；本地 owner 安装的程序集，远程无法注入。
- 验证：`GET /api/sdk/plugins` 可见 `own-data` 项。

## 验证记录（本机 smoke test，无 UI Tree 时优雅失败）

宿主侧（重建后的工作区宿主，`--port 18777`）：

- `GET /api/sdk/plugins` → `ok=true`、`errors=[]`，含 `own-data`（“本人数据只读插件”，source=built-in）与 `session-snapshot`（local-assembly）。
- `GET /api/sdk/chat?who=filehelper` → `{"ok":false,"operation":"chat","error":"sdk_read_failed",…}` —— 优雅失败，**不是 404**（证明路由与子进程链路已通）。
- `GET /api/sdk/chat`（缺 who）→ `{"ok":false,"error":"invalid_request","message":"会话标识 who 不能为空。"}`
- `GET /api/sdk/chat?who=..%2Fetc` → `{"ok":false,"error":"invalid_request","message":"会话标识包含非法字符。"}`
- `POST /api/sdk/plugins/run {id:"own-data",operation:"contacts"}` → 经插件路由，同样优雅失败。
- `POST /api/sdk/plugins/run {id:"nope"}` → 404 `plugin_not_found`。
- `POST /api/sdk/login` → `ok:true`（微信已在运行，提示本人扫码）。

构建与静态取证：

- `WeChatSdkHost` 0 警告 0 错误；控制台 `--selftest` 12 项 PASS；`verify_console_chat_route.py` 9/9 PASS。

## 已知限制
- 聊天读取需先在 Windows 宿主侧让官方微信主窗口处于「已登录 + UI Tree 开放」状态，否则返回 `sdk_read_failed`（设计如此，非 bug）。
- Android 端 CSV 导出落在应用沙盒 `AppDataDirectory`，需文件管理器查看；如需「下载」目录可后续接 FileSaver。
- MAUI Windows 端未单独构建（本机已验证 Windows 宿主；手机经 LAN 连宿主即满足「Windows 直连优先」）。
