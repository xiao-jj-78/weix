# 微信工作台 · 真机验证清单与排查指南

> 面向「手机独立版 1.3」在你本人小米手机 + 微信上的实测，附电脑版联动验证。
> 目标：把文档里标「未真机验证」的项，逐条确认 **过 / 不过**，并记录现象与日志。
> 我只准备清单和排查项；扫码登录、读会话、点赞、通知回复都需**你本人**在设备上操作。

## A. 先读：边界与红线

- **只用你本人账号**，先用**标记的测试数据 / 测试好友**，不要一上来就对真实好友群发/批量点赞。
- **顺序**：先手动功能（AI 预览、悬浮球、单条通知回复、单轮点赞）→ 全部正常后，再考虑开「自动回复 / 自动巡检」。
- **点赞 / 回复是否成功，以微信 App 内显示为准**，本工具返回「已提交」≠ 已送达。
- 每一步都可**随时停止**（见 §M 止损）。
- 合规：界面自动化操作微信违反微信用户协议，频繁可能触发风控甚至封号；请勿用于骚扰、批量营销等违法违规用途。后果自负。

## F. 通知使用权 + 快捷回复（手动，先别开自动）

| # | 步骤 | 期望 | 失败排查 |
| --- | --- | --- | --- |
| F1 | App 内「开启通知使用权」，在系统里授权本应用 | 授权成功（设置搜「通知使用权」） | MIUI 路径：设置→通知与控制中心→通知使用权；找不到就系统设置里搜关键字 |
| F2 | 让测试好友发一条消息，进「微信消息」 | 只看到官方 `com.tencent.mm` 的新通知；不读聊天库 | 收不到：确认微信「显示通知正文」已开、通知使用权已授、服务未被 MIUI 杀 |
| F3 | 选中该通知→生成回复→核对→「确认并回复所选通知」 | 仅当这条通知**有快捷回复入口且未过期**才提交；提示「已提交」 | 无快捷回复入口→用「复制回复」手动粘贴；微信版本/通知类型不支持时会明确提示 |
| F4 | 去微信核对 | 会话里确实出现你的回复 | 只提示已提交但微信没有→属「入口过期/内容变化」，按设计应手动粘贴 |

## J2. 「微信数据」页（一键登录 / 通讯录 / 聊天 / 导出）

> 这是三功能落地后新增的一页，需要 **Windows 宿主在跑**（手机经同一局域网连宿主，或桌面版直连 `127.0.0.1:18766`）。
> 合规：只读本人已登录账号；登录只打开官方客户端由你本人扫码；导出文件落本机并显示路径。

| # | 步骤 | 期望 | 失败排查 |
| --- | --- | --- | --- |
| J2-1 | 先起宿主：`cd 微信SDK宿主` → `微信自动化控制台.exe --port 18766` | 宿主监听 `127.0.0.1:18766` | 端口占用换端口，并在 App 里同步填；确认已装 .NET 10 运行时 |
| J2-2 | App「工作台」页填 `电脑IP:18766` → 连接电脑 → 切到「**微信数据**」页 | 页面顶部显示「已连接 http://电脑IP:18766（本人数据只读，仅本机）」 | 显示「未连接」→ 回工作台页确认 IP/端口已保存 |
| J2-3 | 点「**一键登录微信**」 | 返回提示已请求官方微信登录窗口；**桌面**出现官方微信登录窗 | 桌面无反应→确认宿主进程在跑、微信未以其他账号占用 |
| J2-4 | 点「**读取通讯录（用户表）**」 | 列出本人通讯录姓名 | 返回 `sdk_read_failed`→ 微信主窗口未开放 UI Tree（**设计如此，非 bug**）：在官方微信里打开主界面后重试 |
| J2-5 | 在 `who` 框填 `filehelper`（文件传输助手）→ 点「**读取聊天记录**」 | 列出该会话历史消息 | 同上；`who` 填错会返回空或 `sdk_read_failed` |
| J2-6 | 点「**导出通讯录与聊天为本地 CSV**」 | 提示已导出并显示本机路径 `…/wechat_data_*.csv` | 手机端落在应用沙盒目录，需文件管理器查看；桌面版路径直接可见 |
| J2-7 | 核对导出文件 | 内容与你看到的列表一致，仅本人数据 | 内容为空→先完成 J2-4 / J2-5 |

**宿主接口自测（不用 App，直接用 curl 也行）**

```bash
curl "http://127.0.0.1:18766/api/sdk/plugins"                      # 应含 own-data
curl "http://127.0.0.1:18766/api/sdk/chat?who=filehelper"          # 无 UI Tree 时应为 sdk_read_failed，不是 404
curl -X POST "http://127.0.0.1:18766/api/sdk/plugins/run" \
     -H "Content-Type: application/json" \
     -d '{"id":"own-data","operation":"contacts"}'
```

## K. 抓日志（失败时才用）

- **手机日志（adb）**：小米开 USB 调试（部分 MIUI 需登小米账号 + 插 SIM 才给加调试权限）。
  ```bash
  adb devices                       # 确认已连接并授权
  adb install -r "<apk路径>"        # 覆盖安装保留数据
  adb shell am start -n com.wechatlike.maui/crc64ff0ba2210524e9e2.MainActivity   # 直接拉起
  adb logcat -c                     # 清旧日志
  # ……复现问题……
  adb logcat -d | grep -iE "AndroidRuntime|com.wechatlike|FATAL|System.err"      # 抓崩溃/错误
  ```
- **电脑日志**：`升级版-微信工作台/data/console-out.log`、`console-error.log`、`logs/sdk_host.log`。
- 记录格式：**时间 + 步骤号 + 现象 + 关键日志行**，便于定位。

## M. 止损与回退

- 自动回复：App 内「立即关闭自动回复」。
- 自动巡检：朋友圈辅助里关闭「自动巡检」（会清除该设置）。
- 悬浮/服务：首页「停止助手」→工具球与服务一起停。
- 都不行：系统设置里停用本应用的无障碍/通知服务，或强制停止；极端情况卸载 App。
