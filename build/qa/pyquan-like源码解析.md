# pyquan-like 源码解析与本项目适用性

解析日期：2026-10-16。参考仓库：[Throokie/pyquan-like](https://github.com/Throokie/pyquan-like)，固定提交 `930186cc8aa5477bf6492759fb1a83f53991d6ac`。本次只克隆并静态阅读，没有安装其依赖、执行自动化或连接真实微信。

## 实际工作流程

`client.py` 是电脑端 Python 控制程序：列出 ADB 设备 → 人工选择设备 → 截图 → 通过模板或 SIFT 校准评论与点赞按钮 → 循环匹配评论按钮 → ADB 点击菜单和推算的点赞位置 → 滑动继续寻找。每台设备创建一个线程。截图留在电脑临时文件中，正常退出时尝试清理。

`wechat_like_cv_server.py` 是 FastAPI 视觉服务，默认监听 `0.0.0.0:9000`。`POST /vision/process` 接收目标截图与模板文件，通过 OpenCV SIFT、FLANN、RANSAC 单应变换估计模板位置。客户端优先本地多尺度模板匹配，必要时调用该服务。

三个 PNG 分别用于评论菜单、空心点赞图标和朋友圈标题。设备操控依赖 ADB，手机或模拟器需另有 ADB 授权及连接环境。代码不提供 APK、微信登录实现、云端微信客户端或独立手机执行服务。

## 与需求对比

| 需求 | 参考源码实际能力 | 本项目处理 |
|---|---|---|
| 手机离开电脑独立使用 | 控制程序和视觉服务均为 Python / ADB 路线 | 保留 MAUI Android 本地执行，不引入电脑依赖 |
| 识别并勾选好友 | 没有通讯录接口、好友选择、作者 OCR 或 wxid 匹配 | 新增可见微信界面识别及勾选列表，不再要求输入作者名 |
| 按所选好友点赞 | 按屏幕上的评论按钮位置处理，不校验作者 | 保留本项目作者名单、唯一控件和页面校验 |
| 别人一发布立刻点赞 | 截图和滑动循环，不是好友发布事件订阅 | 本项目有条件约 15 秒巡检，不能承诺即时 |
| AI 答复 | 没有模型接口或回复会话管理 | 保留现有兼容接口、预览和通知回复流程 |
| 多微信管理 | 多个 ADB 设备线程，不是微信账号身份管理 | 与本项目官方窗口管理分开 |

## 可参考的思路

- 模板的多尺度匹配适应一定的屏幕缩放。
- 匹配坐标的空间聚类可减少同一图标的重复候选。
- 截图前后差异可以作为界面变化信号，但不能证明目标用户已点赞成功。
- 多设备任务应有独立状态、停止控制和错误反馈。

本轮没有将其 Python 或模板文件复制进产品，也没有把参考程序作为新的自动点赞驱动。README 中的宣传性准确率、“低封号风险”等不能作为本项目的验证结论。

## 具体问题与限制

1. **无按好友过滤。** `execute_pipeline` 取最上方有效评论按钮；`process_target` 依赖校准得到的相对位置点击，没有作者或唯一动态身份校验。
2. **点赞计数不是成功计数。** `like_count` 在触摸提交后增加，`wait_for_ui_change` 的结果未决定是否计数。达到限额后回到顶部并归零继续，限额不是整次任务的最终停止上限。
3. **已赞判断较弱。** `check_liked_status` 在推算区域检测红色像素，未核对明确的“取消赞”状态。
4. **SIFT 特征不足处理不完整。** `for m, n in matches` 假定每个 KNN 结果都有两个邻居；单邻居场景可能异常，接口捕获后返回失败，客户端可降级或跳过，但不能视作完整健壮处理。
5. **输入和服务边界不足。** 上传未见认证、明确大小限制和解码前验证；默认监听全部网卡，不宜直接暴露公网。图片解码失败会进入异常响应。
6. **依赖声明有问题。** `shlex` 是 Python 标准库，不应作为 `shlex>=1.0.0` 的第三方依赖；FastAPI 的 `File` / `Form` 文件上传还需要 `python-multipart`，当前 requirements 没列出。
7. **设备及路径兼容。** ADB 可执行路径直接拼接到字符串，再经 `shlex.split` 解析，Windows 含空格路径易出错。临时截图名直接使用设备 ID，网络 ADB 的 `IP:端口` 在 Windows 文件名中可能失败。
8. **多线程监控闭包。** `monitor_only` 引用循环中的 `bot`，没有通过默认参数固定，线程启动时机可能使监控对象与原先设备不一致。
9. **启动与停止。** 视觉服务进程启动后没有就绪检测；截图失败的监控循环没有等待，可能忙循环。线程使用无限循环，缺少单设备可见停止控制。
10. **未见可核实性能测试。** 根目录没有对应测试套件或基准，README 的数字不能从代码审计证明。

## 本项目好友选择的实现边界

识别仅在本人点击“识别微信当前页”时读取官方微信可见的辅助节点。通讯录需要页面标题、列表、头像和单个名字行共同确认；朋友圈需要作者与头像、同一动态评论菜单结构匹配。聊天正文、服务入口、未知界面不作为好友。

候选暂存在手机内存；仅保存所勾选的最多 20 个显示名。不会上传通讯录到云端或 AI。已发现同名的候选不能保存或自动执行；昵称、备注均不是微信唯一 ID，跨页面同名和切换账号仍需人工核对，建议唯一备注、换号后清空重选。没有取得完整通讯录或真实 wxid 的能力，也不伪造头像与好友数据。

本轮规则测试使用合成界面树，只证明规则对这些输入的结果；微信真实控件、中文/英文版本与小米系统兼容性仍需真机验证。
